# SonarCloud coverage gate

Backend CI runs the full Maven test suite, generates a JaCoCo XML report for each service, submits the multi-module Maven analysis to SonarCloud, and waits for the quality gate. Frontend CI runs Vitest with coverage enabled and uploads its LCOV report as an artifact.

Configure SonarCloud's quality gate to require **at least 80% Coverage on New Code**. Keep the gate assigned to this project; `sonar.qualitygate.wait=true` makes the backend job fail when the analysis fails its assigned gate. Existing code coverage is tracked separately and is not treated as new-code coverage.

## Repository setup

Set these GitHub repository values before running CI:

- Secret `SONAR_TOKEN`: a SonarCloud token permitted to analyze this project.
- Variable `SONAR_ORGANIZATION`: the SonarCloud organization key.
- Variable `SONAR_PROJECT_KEY`: the project key.

Require the **build-backend** check on protected branches if the Sonar gate must block merges. GitHub repository administrators must configure the hosted quality gate and branch protection; those settings cannot be committed in this repository.

JaCoCo reports are generated by Maven's `verify` phase at `backend/<service>/target/site/jacoco/jacoco.xml`. The Angular test command uses `--coverage` and writes `webapp/coverage/lcov.info`.
